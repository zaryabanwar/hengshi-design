## Findings and reviewed boundaries

**No severity-rated correction is required for this proposed slice.**

- **Independent identities and cycles:** the six required fields reuse public
  identifier/path/digest domains. `html_artifact_id` is a separately planned ID,
  not its own digest. The closed record excludes manifest/HTML self-digests,
  script/unit selectors, private admission/configuration, personal identity,
  consent/options and grants. Build/catalogue generation precedes binding/final
  HTML and manifest generation follows final artifact hashes. The binding stays
  outside catalogue-covered units and cannot cause a release-specific code rewrite.
  This retains the preceding one-way identity graph without an HTML/catalogue hash
  cycle. Exact generation and serving association still require actual enforcement.
- **Inert whole-document binding:** lines 693–710 recommend one compiler-owned
  `script` data block in the head before startup, exact reserved ID and
  `type="application/json"`, with only those two attributes. Whole-document ID
  uniqueness and rejection of competing elements prevent reliance on first-match
  lookup. No `src`, event handler or executable type is allowed. This restriction
  is specific to the binding; it does not pretend to validate other JSON-LD or
  arbitrary data blocks through the same schema.
- **Restricted canonical encoding:** field/key domains are fixed ASCII and exclude
  characters that could create a closing-script or HTML parser transition. Exact
  JCS UTF-8 output, no BOM/indentation/surrounding whitespace, validated projection,
  no unvalidated interpolation and no HTML-entity encoding inside raw text form a
  coherent candidate encoding. A broader future field needs a reviewed amendment.
  Duplicate-key/non-JSON rejection before schema and canonical text comparison are
  explicitly required; shape alone never claims serialization/parser enforcement.
- **Publisher, final HTML and actual code:** lines 712–740 require current private
  admission, exact route/path/HTML kind/association, catalogue/build agreement,
  final HTML digest/length and script/style/preload/import/dependency/policy agreement.
  These remain actual-boundary obligations. Comparing copied digest strings does
  not prove emitted or executed code identity. Startup's later catalogue check
  explicitly cannot authenticate code already executed; trusted admission and
  controlled code serving must establish that independently. No public binding
  chooses an executable or exposes private job/approval records.
- **Pinned reads, gates and authority:** startup retains an immutable original
  document-context copy and uses only validated IF-PUB-02 exact-release lookup.
  It requires a verified eligible 200 envelope and associated catalogue; no
  IF-PUB-01 repair, URL/query/storage substitution or later DOM mutation can replace
  the binding. This is consistent with the existing validator-free/no-store GET
  profile: a 304 or stored envelope does not supply a fresh verified context or
  extend eligibility. The binding grants neither World entry nor sound consent.
  Initial semantic HTML and approved Book/Contact links remain usable without
  successful JavaScript; failed dependent enhancements recover truthfully without
  private resubmission or approval of withdrawn content. Current applicable
  authority is rechecked before protected actions/resources.
- **Navigation:** full documents have their own verified bindings; later client
  navigation retains eligible release/build pin and separately checks requested
  route/content association. Rewriting the original data block cannot certify a
  different HTML artifact. Exact router/data mechanics and normalization remain
  held while canonical redirects and semantic completeness retain authority.
- **Integrity scope:** external script `integrity` protects its initial fetch, not
  automatic coverage of all imported modules, lazy chunks, workers or WASM. CSP,
  SRI and catalogue raw-byte checks remain distinct. Exact transitive integrity/
  serving association and browser evidence are held; no import-map integrity,
  draft SRI API, worker or Blob execution permission is selected.
