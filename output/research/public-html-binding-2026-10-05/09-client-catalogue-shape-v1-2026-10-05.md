## Findings and coverage

**No severity-rated correction is required for this proposed slice.**

- **Closed shape and identity:** root, unit, entries container, each entry, profile
  and extension-rule records are closed; required arrays/objects/scalars have
  explicit types and domains. Existing publication identifier/digest/key domains
  are reused via fixed local references. No self-build digest, release/manifest
  identity, public URL, callback, options or executable settings field is admitted.
  Canonical catalogue bytes retain the preceding independent identity rule;
  catalogue/binding/HTML and scene/model/collision/audio-content inventory is
  excluded semantically, not asserted by filename shape alone.
- **Public build configuration and private admission:** lines 573–580 distinguish
  public normalized code-build configuration from the private render configuration.
  Secrets, machine/provider settings and release-specific rendering inputs are
  excluded. Toolchain-lock/config hashes must agree with admitted inputs; a hash
  alone does not prove stable graph compatibility or reproducibility. The actual
  relationship and private authority are rechecked at the real publisher boundary.
  Nothing exposes private binding/job/approval/configuration records to a browser.
- **Unit interpretation and mapping:** lines 582–604 require exact emitted byte
  digest/length, supported MIME/role agreement, actual resource behavior, traversal
  and reserved-key rejection, unique same-release `shared_asset` mapping and exact
  dependencies/stream coverage. Worker/decoder roles grant no execution or browser
  permission. The inherited key grammar and lower-case parameter-free MIME grammar
  are accurately described as shape limits; neither proves safe resolution or
  correct bytes. The safe-integer ceiling is capacity, not a selected memory budget.
- **Required graph and lazy indexes:** required static byte prerequisites must form
  a resolved acyclic graph; actual emitted cross-unit cycles fail until reviewed
  packaging resolves them. Source-level structure within one unit is not falsely
  treated as another public graph. Optional IDs index actual lazy relationships
  and cannot hide a required import or authorize eager acquisition. Actual CSS,
  worker/decoder and other resource requests remain part of inspected build coverage.
- **Entry and transfer gates:** semantic/world are required fixed entries; audio is
  optional and fixed to enablement when present. Each has nonempty unit IDs, and
  the schema enforces its entry activation enum. Complete closure may not acquire
  later-gated units, so semantic entry cannot pull World/audio-only units and World
  entry cannot pull audio-only units. Earlier permitted shared core code remains
  reusable. Absence of split audio code does not remove sound or waive consent for
  sound bytes/playback. Silent control/UI code may exist earlier while World and
  audio resource/initialization gates retain authority. Gate metadata never grants
  a visitor action.
- **Profiles and decoder inventory:** profiles declare glTF 2.0, base decoder units
  and extension-specific interpretation/optional-ignore inventories of fixed
  compiled behavior. Ignored rules have empty decoder arrays as enforced by shape.
  Existing unit/role support and unique extension/profile identities are semantic
  checks. Required extensions must be interpreted; optional ignore needs verified
  evidence that essential geometry/material/content remains correct. Deriving a
  model's decoder set from the base plus actually used interpreted extensions,
  mapping it to same-release artifacts and agreeing with the resource-map inventory
  and required closure is explicit preparation work. It does not preload all
  profiles or supply the separate collider/navigation binding.

This is coherent with the reviewed catalogue/bootstrap and glTF resource-map
logic, private preparation identity, publication serving/withdrawal and browser
security/resource rules, and loading/F3D-04–07/F3D-14 obligations. The unchanged
logical proposal excludes self/release/HTML/binding hash cycles and payload-driven
code discovery; the new shape does not reopen those boundaries. Shape success is
not registration, eligibility, collision readiness, resource ownership or permission.
